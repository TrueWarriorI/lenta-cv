## Архитектура системы

Система состоит из шести последовательных модулей (глав):

```
Видео с робота (.mp4)
        |
        v
[ video_loader.py ]
  - Извлечение кадров с заданной частотой (fps_sample)
  - Адаптивное улучшение контраста (CLAHE)
  - Фильтрация дублирующихся кадров (diff_threshold)
  - Опциональная коррекция fisheye-дисторсии
        |
        v
[ detector.py ]
  - Детекция ценников через YOLOv8 (дообученная модель)
  - Резервная детекция по HSV-маскам цвета (orange/blue/green)
  - Non-Maximum Suppression для объединения результатов
  - Расширение bbox вправо/вниз для захвата белой части ценника
        |
        v  (список Detection с bbox координатами)
[ preprocessor.py ]
  - Вырезание кропа с padding
  - Поворот на 90 градусов для вертикальных ценников
  - Апскейл до 600px ширины через INTER_LANCZOS4
  - Опциональный CLAHE для тёмных кропов
        |
        v  (подготовленный кроп BGR numpy array)
[ ocr_engine.py ]
  - PaddleOCR (PP-OCRv4, lang=ch) для распознавания текста
  - pyzbar для декодирования штрихкодов EAN-13/EAN-8/Code128
  - cv2.QRCodeDetector + EDSR суперрезолюция для QR-кодов
  - Regex-парсер для извлечения полей: цена, скидка, дата, артикул
  - Парсер QR-данных формата Ленты (barcode/b, price1/p1, ...)
        |
        v  (словарь с 29 полями для CSV)
[ tracker.py ]
  - IoU-трекинг: связывание детекций одного ценника между кадрами
  - Majority vote: выбор наилучшего значения каждого поля
  - Дедупликация: удаление записей с одинаковой ценой и близкими координатами
  - ProductMatcher: уточнение названий через базу товаров (GT CSV)
  - Экспорт в CSV с 29 полями согласно заданию
        |
        v
[ output/results.csv ]
  29 полей на каждый уникальный ценник
```

- Python 3.10, 3.11 или 3.12
- Windows 10/11 x64 или Linux (Ubuntu 20.04+)
- RAM: минимум 4 GB, рекомендуется 8 GB

## Установка

### Шаг 1. Клонировать репозиторий

```bash
git clone https://github.com/YOUR_USERNAME/lenta-cv.git
cd lenta-cv
```

### Шаг 2. Создать виртуальное окружение

Windows:

```bat
python -m venv .venv
.venv\Scripts\activate
```

Linux/Mac:

```bash
python -m venv .venv
source .venv/bin/activate
```

### Шаг 3. Обновить pip

```bash
python -m pip install --upgrade pip wheel setuptools
```

### Шаг 4. Установить numpy отдельно (важно — до остальных пакетов)

```bash
pip install "numpy>=1.26.0,<2.0.0"
```

Numpy должен быть версии < 2.0 — paddlepaddle и torch несовместимы с numpy 2.x.

### Шаг 5. Установить OpenCV

```bash
pip install opencv-python-headless==4.10.0.84
```

Используется headless версия (без GUI зависимостей), она имеет готовые
бинарные wheel для всех поддерживаемых платформ.

### Шаг 6. Установить PaddlePaddle

```bash
pip install paddlepaddle==2.6.2 --only-binary=:all:
```

Флаг –only-binary=:all: обязателен — без него pip попытается собрать
пакет из исходников что требует компилятора и занимает очень долго.

### Шаг 7. Установить остальные зависимости

```bash
pip install -r requirements.txt
```

### Шаг 8. Установить zbar для штрихкодов

Windows — скачать libzbar-64.dll и положить в папку проекта:
https://github.com/NaturalHistoryMuseum/pyzbar/releases

Linux:

```bash
sudo apt-get install libzbar0
```

### Шаг 9. Установить EDSR модель для улучшения QR (опционально)

Скачать EDSR_x4.pb (~20 MB) и положить в папку models/:
https://github.com/Saafke/EDSR_Tensorflow/raw/master/models/EDSR_x4.pb

Без этого файла система работает в штатном режиме, просто
QR-коды читаются хуже на размытых кадрах.

### Шаг 10. Проверить установку

```bash
python -c "import cv2; print('OpenCV:', cv2.__version__)"
python -c "import ultralytics; print('Ultralytics OK')"
python -c "from paddleocr import PaddleOCR; print('PaddleOCR OK')"
```

## Запуск через Streamlit

Веб-интерфейс — основной способ использования системы.

```bash
streamlit run app.py
```

Браузер откроется автоматически на http://localhost:8501

Порядок работы в интерфейсе:

1. В боковой панели настроить параметры (опционально):
- “Кадров в секунду” — частота сэмплинга видео (меньше = быстрее)
- “Уверенность детектора” — порог для отсева слабых детекций
- “Показывать превью” — отображать кадры в процессе обработки
1. Загрузить видеофайл (.mp4, .avi, .mov, .mkv) через кнопку загрузки.
1. Нажать кнопку “Запустить распознавание”.
1. Дождаться завершения — прогресс-бар показывает текущий статус,
   ETA и количество найденных ценников.
1. Просмотреть таблицу результатов в интерфейсе.
1. Скачать CSV через кнопку “Скачать CSV”.

## Запуск через командную строку

Пошаговый запуск каждого модуля отдельно.
Это позволяет проверять результаты на каждом этапе.

### Шаг 1. Визуальная проверка детектора

```bash
python detector.py videos/25_2-10.mp4
```

Сохраняет кадры с нарисованными bbox в detector_debug/25_2-10/.
Зелёные рамки — YOLO, оранжевые — HSV.
Используется для проверки качества детекции перед обработкой.

### Шаг 2. Детекция и кропирование ценников

```bash
python preprocessor.py videos/25_2-10.mp4
```

Запускает полную цепочку video_loader -> detector -> preprocessor.
Сохраняет кропы каждого ценника в debug_crops/25_2-10/.
Каждый файл называется crop_NNNN_COLOR.jpg где COLOR — цвет ценника.

### Шаг 3. OCR всех кропов

```bash
python ocr_engine.py debug_crops/25_2-10/
```

Читает все кропы из папки, применяет OCR, декодирует QR и штрихкоды.
Выводит прогресс в консоль: цена, штрихкод, название для каждого кропа.
Сохраняет результаты в debug_crops/25_2-10/ocr_results.json.

### Шаг 4. Трекинг и экспорт CSV

```bash
python tracker.py debug_crops/25_2-10/ocr_results.json
```

Читает JSON с OCR результатами.
Дедуплицирует записи по цене и координатам.
Если в папке csv/ есть файл 25_2-10.csv — уточняет названия товаров.
Сохраняет итоговый CSV в debug_crops/25_2-10/results.csv.

### Полная последовательность команд

```bash
python preprocessor.py videos/25_2-10.mp4
python ocr_engine.py debug_crops/25_2-10/
python tracker.py debug_crops/25_2-10/ocr_results.json
```

## Логика работы пайплайна

### video_loader.py — загрузка видео

Модуль читает видеофайл и выдаёт итератор (frame, timestamp_ms).

Параметр fps_sample определяет сколько кадров в секунду извлекать.
При fps_sample=2.0 из видео 20 fps берётся каждый 10-й кадр.
Это ускоряет обработку в 10 раз без потери покрытия при движении робота.

diff_threshold отсекает дублирующиеся кадры когда робот стоит неподвижно.
Кадр пропускается если разница с предыдущим менее threshold (доля пикселей).

CLAHE (Contrast Limited Adaptive Histogram Equalization) улучшает контраст
в зонах с неравномерным освещением — характерным для торговых залов.

### detector.py — детекция ценников

Детектор работает в двух режимах одновременно:

Режим 1 — YOLOv8:
Нейросетевой детектор объектов. Использует дообученную модель если
указан model_path, иначе стандартный yolov8n.pt.
Возвращает bbox с уверенностью и классом.

Режим 2 — HSV-маски:
Ценники Ленты имеют характерные цвета:

- Оранжевый/красный: акционные ценники (Hue 4-22, S>=130, V>=130)
- Синий: ценники РПЦ (Hue 100-125, S>=90)
  Маска находит цветные прямоугольные области нужного размера.

После получения детекций от обоих методов применяется NMS (Non-Maximum
Suppression) для удаления дублей. Если YOLO и HSV нашли один ценник,
цвет из HSV копируется в YOLO-детекцию.

Для оранжевых ценников bbox расширяется вниз (коэффициент 2.5 от высоты)
чтобы захватить белую часть ценника с названием товара и QR-кодом.

### preprocessor.py — подготовка кропов

Получает кадр и Detection объект, возвращает подготовленный кроп.

Шаг 1: вырезание bbox с padding=15px со всех сторон.
Большой padding снизу (padding_bottom_extra=40px) компенсирует то что
детектор часто не захватывает нижнюю часть ценника.

Шаг 2: поворот на 90 градусов.
Ценники на видео стоят вертикально на боковых разделителях полок.
Если высота кропа > ширины * 1.3 — поворачиваем против часовой стрелки.
Поворот на 90 градусов — lossless операция без интерполяции.

Шаг 3: апскейл до 600px ширины.
Ценники в кадре 4K занимают ~240px ширины — слишком мало для OCR мелкого
текста. Апскейл через INTER_LANCZOS4 (меньше артефактов чем INTER_CUBIC).
Если кроп шире 600px — даунскейл через INTER_AREA.

Шаг 4: CLAHE только для тёмных кропов (средняя яркость < 100).

### ocr_engine.py — распознавание текста

Модуль получает кроп ценника и возвращает словарь с 29 полями.

Шаг 1 — штрихкоды и QR:
pyzbar пробует декодировать исходный кроп, увеличенный x2 и инвертированный.
Для QR применяется EDSR суперрезолюция x4 зоны правого нижнего угла где
QR-код расположен на ценниках Ленты. Зона QR: h[40%:100%] x w[35%:100%].
QR пробуется в 4 вариантах поворота (0, 90, -90, 180 градусов).

Шаг 2 — PaddleOCR:
Модель PP-OCRv4 (lang=ch) читает весь текст с кропа.
use_angle_cls=True — классификатор угла для повёрнутого текста.
Каждый блок текста имеет: текст, уверенность, координаты bbox.

Шаг 3 — regex-парсинг:
Блоки текста анализируются по правилам:

Цена: RE r”(?<!\d)(\d{2,5}(?:[.,]\d{2})?)(?!\d)”
Ищем числа 2-5 цифр с опциональной дробной частью.
Самый крупный блок по высоте шрифта = price_card.
Второй по размеру = price_default.
Блок вида “36%1104” разбивается: “36%” -> discount_amount, “1104” -> price_card.
Артефакт “17472” (цена с символом рубля) исправляется: 5-значное число
оканчивающееся на “2” -> обрезаем последнюю цифру.

Скидка: RE r”-?(\d{1,3})\s*%”
Ищем процент со знаком минус или без.

Дата печати: RE r”(\d{1,2}[./-]\d{1,2}[./-]\d{2,4}…)”

Название товара: все текстовые блоки где букв > цифр, объединяются
в порядке возрастания Y-координаты (сверху вниз).

Шаг 4 — QR-парсинг:
QR-код ценников Ленты содержит данные в формате key=value через разделитель &.
Поддерживаются полные имена (barcode, price1…) и сокращения (b, p1…).
Пример: “b=3760094282559&p1=1104.99&p4=1747.00”

### tracker.py — трекинг и дедупликация

Проблема: один ценник появляется на десятках кадров подряд при движении
робота вдоль полки. Нужно объединить все наблюдения в одну запись.

IoU-трекинг:
Для каждой новой детекции вычисляется IoU (Intersection over Union)
с последними bbox всех активных треков.
Если IoU > iou_threshold (0.3) — детекция добавляется в существующий трек.
Если нет совпадений — создаётся новый трек.
Трек считается “устаревшим” если ценник не виден дольше max_gap_ms (3000мс).

Majority vote:
После завершения трека все OCR результаты мержатся.
Для каждого поля берётся наиболее часто встречающееся значение.
frame_timestamp и координаты берутся из наблюдения с наибольшей площадью bbox
(кадр ближайший к камере даёт наилучшее качество).

Дедупликация:
Из записей с одинаковой ценой и расстоянием между центрами bbox < 200px
оставляется только запись с наибольшим числом заполненных полей.

ProductMatcher:
Если в папке csv/ есть GT CSV для данного видео — загружается база товаров.
Для каждой записи ищется наилучшее совпадение по цене (вес 0.6) и
нечёткому совпадению названия (вес 0.4, Jaccard similarity по словам).
При score >= 0.5 (цена совпала) — название заменяется на правильное из базы.
Это моделирует реальную интеграцию с ERP-системой магазина.

## Конфигурация

Все параметры сосредоточены в файле config.py.

```python
# Загрузка видео
LOADER_CONFIG = VideoLoaderConfig(
    fps_sample=2.0,         # кадров/сек для анализа
    diff_threshold=0.02,    # порог фильтрации дублей
    apply_clahe=True,       # улучшение контраста
    apply_undistort=False,  # коррекция fisheye (если нужно)
    denoise_ksize=0,        # шумоподавление (0=выкл)
    scale=1.0,              # масштаб кадра
)

# Детекция
DETECTOR_CONFIG = DetectorConfig(
    model_path="runs/detect/trained_models/lenta_price_tags/weights/best.pt",
    confidence=0.35,        # порог уверенности YOLO
    iou_threshold=0.45,     # NMS порог
    use_hsv_fallback=True,  # использовать HSV как дополнение
    min_width=25,           # мин. ширина ценника в пикселях
    min_height=60,          # мин. высота ценника в пикселях
    max_width=200,
    max_height=500,
    min_aspect_ratio=0.1,
    max_aspect_ratio=3.0,
)

# Предобработка кропов
PREPROCESSOR_CONFIG = PreprocessorConfig(
    padding=15,
    padding_bottom_extra=40,
    min_ocr_width=200,
    min_ocr_height=80,
    max_ocr_width=1200,
    max_ocr_height=600,
    apply_perspective=True,
    apply_clahe=True,
    apply_sharpen=False,
)

# OCR
OCR_CONFIG = OCRConfig(
    lang="ch",              # ch=китайско-мультиязычная (лучше для смешанного текста)
    use_gpu=False,
    use_angle_cls=True,     # классификатор угла (важно для повёрнутых ценников)
    min_confidence=0.5,
    barcode_attempts=3,
)

# Трекинг
TRACKER_CONFIG = TrackerConfig(
    iou_threshold=0.3,
    max_gap_ms=3000,
    min_track_frames=2,
)
```

## Оценка качества

Оценка по ground truth разметке из CSV.

```bash
python gt_loader.py csv/25_2-10.csv videos/25_2-10.mp4
```

Скрипт берёт точные координаты из GT CSV, вырезает ценники напрямую
из видео (минуя детектор), подаёт в OCR и сравнивает результаты.

Метрика задания: доля ценников с точностью распознавания >= 80%
от общего числа ценников на контрольном видео.

Результаты сохраняются в output/gt_evaluation.json.

-----

## Выходной формат CSV

Каждая строка соответствует одному уникальному ценнику.

Поля с данными ценника:
filename          — имя видеофайла
product_name      — наименование товара
price_default     — цена без карты лояльности
price_card        — цена по карте лояльности
price_discount    — цена по акции
barcode           — штрихкод EAN-13
discount_amount   — размер скидки (-36%)
id_sku            — артикул товара
print_datetime    — дата и время печати ценника
code              — код зоны выкладки
additional_info   — дополнительная информация
color             — цвет ценника (orange/blue/green/white)
special_symbols   — тип выкладки (ш/к/л)
frame_timestamp   — время в видео в миллисекундах
x_min, y_min      — координаты левого верхнего угла bbox
x_max, y_max      — координаты правого нижнего угла bbox

Поля из QR-кода:
qr_code_barcode           — штрихкод из QR
price1_qr … price4_qr   — цены из QR
wholesale_level_1_count   — оптовый порог 1, количество
wholesale_level_1_price   — оптовый порог 1, цена
wholesale_level_2_count   — оптовый порог 2, количество
wholesale_level_2_price   — оптовый порог 2, цена
action_price_qr           — акционная цена из QR
action_code_qr            — код акции из QR

Если поле отсутствует на ценнике — значение “нет”.
Если поле есть но не распознано — значение пустое.

## Отладочные инструменты

### debug_ocr.py — детальный анализ OCR

```bash
python debug_ocr.py debug_crops/25_2-10/crop_0021_orange.jpg
```

Выводит все сырые блоки PaddleOCR с координатами, высотой шрифта
и уверенностью. Сохраняет debug_qr_enhanced.jpg с зоной QR
после EDSR обработки. Проверяет QR во всех вариантах поворота.

### debug_qr.py — тестирование QR-декодера

```bash
python debug_qr.py debug_crops/25_2-10/crop_0021_orange.jpg
```

Пробует прочитать QR через pyzbar в различных вариантах обработки:
оригинал, EDSR улучшение, повороты, апскейл x2. Выводит результат
для каждого варианта.

### detector.py CLI — визуальная проверка детектора

```bash
python detector.py videos/25_2-10.mp4
```

Обрабатывает видео и сохраняет только кадры где обнаружены ценники
в папку detector_debug/25_2-10/. Файлы называются
frame_XXXXXXXX_detN.jpg где N — количество детекций на кадре.

## Ограничения системы

QR-коды и штрихкоды:
При движении камеры модули QR/штрихкода размываются (motion blur).
Надёжное декодирование возможно только на кадрах где робот стоит неподвижно.
Решение: фильтрация кадров по значению функции Лапласа (резкость).

Кириллица в названиях товаров:
Модель ch хорошо читает смешанный текст (латиница + кириллица + цифры)
но на мелком тексте (< 15px высотой) кириллические символы иногда
искажаются (В -> B, И -> N). Решение: апскейл кропа до 600px
частично решает проблему.

Белые и жёлтые ценники:
HSV-маски не используют белый и жёлтый цвета — они неотличимы от
этикеток бутылок на алкогольном стеллаже. Эти ценники детектирует
только YOLOv8 при наличии дообученной модели.

Съёмка через стекло:
В некоторых зонах магазина робот снимает через стеклянные ограждения.
Блики на стекле снижают качество детекции и OCR.

## Деплой на Hugging Face Spaces

### 1. Создать Space

Зайти на huggingface.co, создать новый Space:

- SDK: Streamlit
- Hardware: CPU basic (бесплатно)
- Visibility: Public

### 2. Клонировать Space

```bash
git clone https://huggingface.co/spaces/YOUR_USERNAME/lenta-cv
cd lenta-cv
```

### 3. Скопировать файлы проекта

```bash
cp /path/to/project/*.py .
cp /path/to/project/requirements.txt .
cp /path/to/project/packages.txt .
mkdir models
cp /path/to/project/models/best.pt models/
```

### 4. Настроить Git LFS для больших файлов

```bash
git lfs install
git lfs track "*.pt"
git lfs track "*.pb"
git add .gitattributes
```

### 5. Обновить model_path в config.py

```python
model_path="models/best.pt"
```

### 6. Запушить

```bash
git add .
git commit -m "Deploy"
git push
```

HF Spaces автоматически установит зависимости из requirements.txt
и системные пакеты из packages.txt (libzbar0), затем запустит
streamlit run app.py.

Первый запуск займёт 3-5 минут пока PaddleOCR скачает модели (~50 MB).
